# StuBara 운영 가이드

## StuBara를 어떤 공간으로 키울까

StuBara는 단순 메모 저장소보다, **바라가 정리한 리서치와 브리핑을 꾸준히 쌓아가는 개인 지식 아카이브**로 가는 게 가장 좋아.

핵심 방향은 이거야.

- **짧은 뉴스 브리핑도 쌓는다**
- **긴 리서치 문서도 쌓는다**
- **나중에 다시 찾아보기 쉽게 구조화한다**
- **폰에서 읽기 편한 형태를 유지한다**

즉, 블로그와 문서 아카이브의 중간 지점으로 가는 게 좋다.

---

## 추천 정보 구조

처음부터 너무 복잡하게 가지 말고, 아래 4개 축으로 시작하는 걸 추천해.

### 1. Notes
가장 기본이 되는 장문 문서 공간.

예시:
- 바이오사이언스 산업동향
- 반도체 산업 메모
- 국제정세 구조 분석
- AI 산업 보고서 요약

### 2. Briefings
짧고 자주 읽는 아카이브.

예시:
- 국제사회 아침 브리핑
- 주간 산업 브리핑
- 월간 테크/정치 요약

### 3. Topics
주제별 모음.

예시:
- 바이오
- AI
- 반도체
- 국제정치
- 공급망

이건 처음부터 페이지를 복잡하게 만들기보다, 문서가 쌓이면 도입하는 게 좋다.

### 4. About
이 공간이 무엇인지 짧게 설명.

예시:
- StuBara는 무엇인가
- 누가 쓰는가
- 어떤 글이 올라오는가

## 문서 스타일 가이드

StuBara의 강점은 **읽기 편함과 정리력**이야. 그래서 문서 스타일도 통일하는 게 좋다.

### 장문 리서치 문서
추천 구조:
- 한줄 요약
- 핵심 변화 3~6개
- 각 변화별 설명
- 산업적 의미
- 앞으로 볼 포인트
- 참고 출처

### 브리핑 문서
추천 구조:
- 오늘의 한줄 흐름
- 핵심 이슈 3~5개
- 각 항목: 핵심 / 영향 / 출처
- 마지막 총정리

### 문체 원칙
- 과장하지 않기
- 사실과 해석 구분하기
- 너무 건조하지 않되, 신뢰감 있는 톤 유지
- 한 문단 너무 길게 쓰지 않기

---

## 디자인 방향

StuBara는 지금처럼 **미니멀하고 세련된 문서형 디자인**을 유지하는 게 좋아.

추천 방향:
- 여백 넉넉하게
- 헤드라인은 강하게
- 본문은 길어도 눈이 안 피로하게
- 포인트 컬러는 지금의 인디고 계열 유지
- 다크모드 지원 유지

추가로 나중에 넣으면 좋은 것:
- 홈에서 최근 글 카드 3개 노출
- 카테고리별 진입 버튼
- 인기/추천 문서 섹션
- 문서별 읽는 시간 표시

---

## 운영 루틴 제안

### 일간
- 짧은 브리핑 추가 여부 확인
- 뉴스 가치가 있는 문서는 briefings에 저장

### 주간
- 쌓인 브리핑 중 의미 있는 주제를 notes로 승격
- 카테고리 정리

### 월간
- 대표 문서 1~2개를 긴 리서치로 정리
- 홈 화면 추천 문서 업데이트

이렇게 하면 StuBara가 단순 저장소가 아니라, 점점 더 **정리된 지식 베이스**가 된다.

---

## 앞으로 추가하면 좋은 기능

우선순위 순서대로 추천하면:

### 우선순위 1
- Briefings 섹션 추가
- 홈에서 최신 문서 노출 강화
- About 페이지 추가

### 우선순위 2
- 태그/주제별 정리
- 검색 최적화
- 문서 썸네일 또는 커버 스타일 강화

### 우선순위 3
- 시리즈 문서 구조
- 연도별 아카이브
- 커스텀 도메인 연결

## GitHub Pages 운영 가이드

### 추천 레포 구조
- `docs-site/`를 사이트 소스로 유지하거나
- 나중엔 사이트 전용 레포로 정리해서 루트 자체를 사이트로 써도 됨

### 배포 방식
- GitHub Actions 기반 Pages 배포 유지
- 문서 수정 → commit → push → 자동 배포

### 보안 원칙
- 토큰은 채팅에 직접 붙이지 않기
- 가능하면 나중에 **SSH 인증**으로 전환하기
- 노출된 PAT는 즉시 revoke 하기

## 현실적인 다음 단계

지금 StuBara에서 바로 다음으로 하면 좋은 건 이거야.

1. **About 페이지 추가**
2. **Briefings 섹션 추가**
3. **홈에서 최근 글/추천 글 UI 개선**
4. **문서 추가 루틴 정하기**

가장 추천하는 순서는:

> About → Briefings → 홈 개선 → 문서 축적

이 순서가 가장 자연스럽고, 사이트가 빠르게 완성도 있어 보여.

---

## 결론

StuBara는 잘만 운영하면 그냥 md 저장소가 아니라,

> **바라가 정리하는 개인 리서치 라이브러리**

가 될 수 있어.

핵심은 많이 만드는 것보다,
**계속 읽히는 구조로 쌓는 것**이야.

그래서 앞으로도 방향은 이렇게 가면 좋아:
- 짧은 브리핑은 자주
- 긴 리서치는 드물지만 밀도 있게
- 디자인은 차분하고 세련되게
- 구조는 단순하지만 확장 가능하게
